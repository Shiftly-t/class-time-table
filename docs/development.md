# 開発ガイド

## コードの変更方針

- 画面描画、状態管理、データアクセス、業務ロジックの責務を区別する。
- 新機能は可能な限り責務ごとのモジュールに分離する。既存の大きなモジュールは回帰試験を追加しながら段階的に整理する。
- 変数・関数名には役割が分かる名前を用い、コメントは処理の理由や制約を説明する。
- JavaScript、CSS、HTMLは2スペースインデントを基本とする。大規模な整形と動作変更は別のコミットにする。
- CSSの詳細度、記述順序、メディアクエリを変える場合は画面を比較する。

## 公開と秘密情報

Firebase Webアプリの設定値とreCAPTCHAサイトキーはクライアントから参照される。これらを認可の代わりに使わない。サービスアカウント鍵、アクセストークン、バックアップ、実際の生徒・講師情報をGitに追加しない。

Hostingではルート直下のHTML・CSS・JavaScriptだけを配布する。文書、テスト、GitHub Actionsの設定は配布対象外。GitHubのリポジトリ公開範囲はHostingとは別で管理する。

## 変更前後の確認

1. 対象の業務機能、権限、データ更新範囲を確認する。
2. 構文チェックと関連する単体テストを実行する。
3. UI変更はPC、スマホ、iPadの通常・分割表示で確認する。
4. バックエンドの変更は別途QA検証し、デプロイ対象を限定する。
5. 本番公開後はHostingファイル照合と主要画面の動作を確認する。

`tests/pr1-review.cjs` は初期のブラウザ回帰テスト。現行のモジュール構成への追従およびPlaywright環境の整備が必要なため、現在のデプロイ必須チェックには含めない。
